# 空闲机器接入托管平台

> **2026-11-06 更新**：Maestro web-runner / 网页测试执行机已移除；本文的「Web 执行机」章节仅作历史参考。设备接入先看 [device-access-and-execution.md](./device-access-and-execution.md)（Android 本机/远程、iOS 模拟器/真机）。
>
> 本文把中心侧（PostgreSQL 台账 + 面板/HTTP 接口）称为「托管平台」，把待接入的机器称为「执行机」。
> 接入一台空闲机器的本质是两件事：**登记一个集群内唯一的主机身份**，再**常驻一个 runner 进程**领取并执行任务。
>
> 事实源：`README.md`「多机部署」「项目机 runner」「远端 Web 测试执行机」；`DESIGN.md` §13.109、§13.165、§13.264。
> 最后核对：2026-11-02。
>
> 以下命令默认在服务仓库根目录执行（`dist/` 已构建）；`<...>` 为占位符。

## 最短路径

- **项目机**：装代码 → 配 `MOBILE_TESTING_HOST_ID` 与中心控制面（或中心 PG）→（旧部署）`host adopt-legacy --local --apply` → `suite runner --project <项目>` → `host register` 补画像 → 面板验收。
- **Android 真机（MCP 原生）**：下载 adb-host 小包 → `adb -a -P 5037 server nodaemon` → 防火墙/SSH 隧道 → MCP 项目配置 `ADB_SERVER_SOCKET` → `run_regression` / `mobile_run_task`。不再使用 Web 执行机/web-runner。

---

## 0. 先判断：这台机器要接成哪一种执行机

平台目前有两种执行机，用途和前置条件不同。先选角色，再按对应流程操作。

| 角色 | 用来跑什么 | 启动命令 | 需要项目目录 | 关键前置 |
|---|---|---|---|---|
| **项目机**（`suite runner`） | 某个项目的移动端回归用例（iOS / Android） | `suite runner --project <项目根>` | 是 | 中心 HTTP 控制面（推荐）或中心 PG、项目已配置 LLM、设备可用 |
| **Web 执行机（已移除）** | Maestro web-runner 已移除；Android 真机改用 MCP 原生 + adb-host | — | — | 见 [android-mcp-native-testing.md](./android-mcp-native-testing.md) |

选择建议：

- 机器上**有项目代码、要跑该项目的回归** → 选项目机。
- 机器是**公共设备池、只跑网页测试任务**，不需要项目目录 → 选 Web 执行机。
- 同一台机器可以同时承担两种角色，但设备租约是**主机级**的，混跑时要注意设备争用；生产环境更推荐一机一角色。

两种执行机共用同一套主机身份规则：`MOBILE_TESTING_HOST_ID` 由你自定义、在集群内必须唯一；它和 `--name` 的显示名是两回事。Windows 快速接入见 [windows-runner-quickstart.md](./windows-runner-quickstart.md)。

## 1. 接入前检查（两种角色共用）

### 1.1 中心侧已就绪

在开始接机器之前，确认中心满足以下条件：

1. **PostgreSQL 可访问**：中心侧必须有 PostgreSQL；配置了 `MOBILE_TESTING_RUNNER_CONTROL_URL` 的项目机/Web 执行机**不需要**该连接串，未配置控制面时仍通过 `MOBILE_TESTING_DATABASE_URL` 直连。
2. **中心服务已启动**：
   - 项目机默认只需 PG；面板与产物预览可选；配置控制面后需要中心 HTTP。
   - Web 执行机需要中心 HTTP 基址（`serve --http`）、控制面（`MOBILE_TESTING_RUNNER_CONTROL_URL`）与 `MOBILE_TESTING_RUNNER_JOB_TOKEN`（至少 16 字符）。
3. **中心版本与执行机版本一致**：执行机部署同一份仓库/同一发布版本，避免 CLI 参数与心跳字段不一致。
4. **队列未被暂停**：`suite queue status --host <主机>` 显示未暂停；暂停的主机不会自动领取任务。
5. **（项目机）项目目录已准备**：项目根目录已生成用例集；执行机首次启动会按 `(host_id, rootPath)` 登记项目行（旧部署先按 2.2 做 `adopt-legacy`）。
6. **（Web 执行机）已有托管 Web 项目**：面板 `?section=jobs` 可下发任务，且已上传 Excel、安装包、脚本等资产。

中心健康检查（仅 HTTP 模式；只接项目机时能连 PG 即可）：

```bash
curl -fsS http://<中心地址>:8765/healthz
```

### 1.2 执行机基础环境

| 检查项 | 要求 |
|---|---|
| Node.js | `>= 20`（`package.json` 的 `engines`） |
| 代码 | 与中心同一版本；`dist/` 已构建 |
| 子模块 | 项目机执行回归需要 `artemis` 子模块；首次克隆用 `--recurse-submodules` |
| 时间 | 与中心同步（心跳、设备租约、任务超时都依赖时钟） |
| 网络 | 配置控制面的项目机/Web 执行机访问中心 HTTP 端口；未配置控制面的项目机访问中心 PG |
| 身份 | `MOBILE_TESTING_HOST_ID` 集群内唯一；不要复制其他机器的 `host-id` |
| 磁盘 | 项目机需要项目目录与 `.artemis/` 写入权限；Web 执行机需要工作目录与资产缓存空间 |
| 权限 | 运行服务的用户能访问设备（adb / Xcode / 模拟器）与项目目录 |

部署代码：

```bash
git clone --recurse-submodules <仓库地址> /opt/AOS-Artemis
cd /opt/AOS-Artemis
npm ci
npm run build
node dist/cli.js doctor
```

项目机还需要准备 artemis 运行依赖：

```bash
node dist/cli.js doctor --install-deps
```

> 不要用 `npm install` 替代 `npm ci` 做可复现部署；仓库有 `package-lock.json`。

### 1.3 主机身份

解析顺序（`src/host/identity.ts`）：

1. `MOBILE_TESTING_HOST_ID`（显式指定，优先级最高）；
2. `AOS_HOST_DIR`（默认 `~/.aos`）下的 `host-id` 文件；
3. 派生 ID（目录不可写时使用；稳定但不可迁移）。

生产环境建议**显式设置 `MOBILE_TESTING_HOST_ID`**，尤其是容器、临时目录、CI 机器：

```bash
export MOBILE_TESTING_HOST_ID=mac-mini-01
export AOS_HOST_DIR="$HOME/.aos"
```

注意事项：

- 集群内每台机器必须不同；两台机器共用同一个 `MOBILE_TESTING_HOST_ID` 会互相顶替心跳，导致任务被反复释放/领取。
- 同一台机器上的本地 MCP 与 `suite runner` 必须解析到**同一个** `MOBILE_TESTING_HOST_ID`（或同一用户下的同一 `AOS_HOST_DIR`），否则同一项目会被登记成两台主机，定向任务与项目归属会分裂。
- 不要从别的机器复制 `~/.aos/host-id`；克隆虚拟机镜像后要重新设置。
- 服务以哪个用户运行，就固定用那个用户的 `AOS_HOST_DIR`；换用户会生成新的主机身份。
- 主机身份一旦变化，旧主机下的项目、任务归属、设备租约都不会自动迁移。

### 1.4 执行机与中心 PG / 控制面

当前有两条路径：

- **Web 执行机（推荐）**：配置 `MOBILE_TESTING_RUNNER_CONTROL_URL` 后，`web-runner` 只发 HTTP 请求到中心 `/panel/api/runners/*`（心跳、领取、租约、任务生命周期），**不打开 PostgreSQL**。执行机不再需要 `MOBILE_TESTING_DATABASE_URL`。
- **项目机（配置控制面）**：`suite runner` 用本地 FileStore 作项目台账，任务读取/状态、case set、run 登记/基线、租约、runner 注册、定时回归窗口与审计走 `/panel/api/runners/suite/*` 资源 API；不打开 PG。
- **项目机 / 未配置控制面的 Web 执行机（回退）**：仍 `openCenterStore()` 直连中心 PG；`PostgresStore.create()` 每次打开会执行幂等建表/迁移（advisory lock 串行化），因此这类执行机需要建表/迁移所需的 DDL 权限，不只是读写队列。生产上应限制 PG 来源、使用专用账号，并评估权限面。

控制面与数据面分工：

- **控制面（HTTP）**：`POST /panel/api/runners/heartbeat`（主机/runner 注册、设备清单、工具、版本、active 任务进度与续租）、`/claim`（服务端内部选机、预占、过期回池、失联回收）、`/leases/renew|release`、`/tasks/:id/begin|progress|terminal|cancel-ack|release`、`/stop`。中心进程持有 PG 并做事务/CAS；执行机只发命令。
- **数据面（HTTP）**：`/panel/api/jobs/:id/spec`、`/panel/api/jobs/:id/assets/:assetId`、`/panel/api/jobs/:id/results` 传大文件与结果，仍用 `MOBILE_TESTING_RUNNER_JOB_TOKEN` + `X-AOS-Host-Id` 鉴权。
- 控制面与数据面共用 runner 鉴权，但**不会回退管理员 token**；优先每主机 token（`AOS_RUNNER_HOST_TOKENS`），未配置时回退全局 `MOBILE_TESTING_RUNNER_JOB_TOKEN` + host 头。`AOS_RUNNER_CONTROL=0` 可关闭控制面（404）。

`suite runner` 的控制面资源 API 已落地（旧 `/suite/op` 已移除）。详见 ADR-0012 与 DESIGN §13.271/§13.272。

## 2. 流程 A：把空闲机器接成项目机（`suite runner`）

适用：这台机器上有项目目录，需要自动领取该项目的回归任务并执行。

### 2.1 准备项目目录

把项目放到执行机的固定路径，例如 `/srv/projects/demo`。确认：

- 项目根目录存在，且包含 `aos.config.jsonc` 或可被项目识别逻辑识别；
- 项目已配置可用的 LLM（`aos_configure` 写入的关联，或项目 `.env` 中的 `AOS_LLM_*` / `DEEPSEEK_API_KEY` 等）；
- 项目已生成用例集（`tests.json` / `tests.xlsx`），并且中心的用例库能解析到；
- 设备已连接或模拟器已启动。

项目根目录必须显式传给 runner，**不要依赖当前工作目录**。

### 2.2 迁移历史数据（仅旧部署需要）

如果中心里存在旧版本留下的、`host_id` 为空的历史项目行，必须在**项目机首次启动新版 MCP/runner 之前**完成认领：

```bash
# 在项目机上执行；只列出本机磁盘上真实存在的 NULL-host 项目
node dist/cli.js host adopt-legacy --local --dry-run

# 确认清单无误后写归属与审计
node dist/cli.js host adopt-legacy --local --apply
```

规则：

- 只在**每台项目机本地**执行 `--local`，不要在中心对所有 NULL 行做一次性认领。
- 顺序很重要：新版 runner/MCP 首次启动会创建 `(host_id, rootPath)` 新行；同路径新行一旦存在，`adopt-legacy` 会跳过 legacy 行。
- 跨机指派使用 `host adopt-legacy --host <id|hostname> --path <rootPath>`；目标主机尚未接入时可加 `--allow-unknown-host`。
- 全新部署、没有 legacy 行时可以跳过这一步（`--dry-run` 会显示无候选）。

### 2.3 首次启动并登记主机

先在前台启动一次，确认心跳和项目登记：

```bash
# 推荐：控制面模式（不直连 PG）
export MOBILE_TESTING_HOST_ID=mac-mini-01
export MOBILE_TESTING_RUNNER_CONTROL_URL='http://<中心地址>:8765'
export MOBILE_TESTING_RUNNER_JOB_TOKEN='<与中心相同的令牌>'

node dist/cli.js suite runner \
  --project /srv/projects/demo \
  --name mac-mini-01
```

> 未配置 `MOBILE_TESTING_RUNNER_CONTROL_URL` 时回退直连 PG：设置 `MOBILE_TESTING_DATABASE_URL` 即可。

看到类似日志说明启动成功：

```text
[runner] 启动：name=mac-mini-01 project=/srv/projects/demo（端 android）
```

此时中心会按心跳创建/更新主机行与项目行。首次启动如果队列里已有待执行任务，runner 会立即领取；这是正常行为。确认日志与面板状态后按 `Ctrl-C` 停止前台进程（或改用 `--once` 只跑一轮），长期运行交给 2.6 的服务管理器。

确认主机已出现后，再补充期望画像（`host register` 只能给已存在的主机写画像）：

```bash
node dist/cli.js host list
node dist/cli.js host register mac-mini-01 \
  --label "Mac mini 01" \
  --owner "QA" \
  --expected-os darwin \
  --expected-hostname mac-mini-01
```

`--expected-os` 使用 Node 的 `os.platform()` 值：`darwin` / `win32` / `linux`。画像不一致只在面板提示漂移，不会拒绝任务。

### 2.4 确认设备清单

runner 心跳会盘点设备，任务只有在「任务目标端 ⊆ 本机设备端」时才会被领取。

- Android：`adb devices` 中状态必须是 `device`，不能是 `unauthorized` 或 `offline`。
- iOS 模拟器：先启动模拟器，`xcrun simctl list devices booted` 能看到。
- iOS 真机：`idevice_id -l` 能看到；如果自动盘点遗漏，可用 `AOS_RUNNER_DEVICES="udid1,udid2"` 显式覆盖（逗号分隔，设置后覆盖所有来源）。
- 双端任务需要单机同时具备双端设备；否则默认不会被领取。需要按端部分领取时，显式设置 `AOS_RUNNER_PARTIAL_CLAIM=1`；只有**没有其他在线 runner 能覆盖全部端**时才会部分领取，缺端不补跑。

> `AOS_RUNNER_DEVICES` 是项目机 runner 的真机补录开关；Web 执行机不要用它覆盖设备盘点，否则工具能力会被标记为未探测。

### 2.5 产物只读服务（可选）

项目机 runner 默认会在 `8770` 端口启动只读产物服务，供面板预览 `.artemis/` 下的清单、用例集、报告、证据等。

```bash
# 默认：监听 0.0.0.0:8770
# 关闭：
node dist/cli.js suite runner --project /srv/projects/demo --name mac-mini-01 --artifact-port 0
```

建议：

- 机器在 NAT/多网卡后，优先用中心能解析的主机名/DNS 名：`AOS_RUNNER_ADVERTISE_URL=http://<主机名>:8770`；**固定 IP 只作兜底**，IP 变化后需要同步修改。
- 中心必须能访问该地址；防火墙只放行中心/办公网段到 8770。不需要预览就设 `--artifact-port 0`。
- 默认无鉴权，暴露范围包含 `.artemis/logs` 与 `.artemis/crashes`；只在受控内网使用。
- 需要鉴权时设置 `AOS_RUNNER_ARTIFACT_TOKEN`（浏览器访问 `/artifact*` 时输入；`/healthz` 豁免）。

健康检查：

```bash
curl -fsS http://127.0.0.1:8770/healthz
```

### 2.6 常驻化

前台运行只适合调试，长期运行交给系统服务管理器。

**systemd（Linux）**

```ini
# /etc/systemd/system/mobile-testing-runner.service
[Unit]
Description=mobile-testing project runner
After=network-online.target

[Service]
Type=simple
User=aos
WorkingDirectory=/opt/AOS-Artemis
EnvironmentFile=/etc/mobile-testing/runner.env
ExecStart=/usr/bin/node /opt/AOS-Artemis/dist/cli.js suite runner \
  --project /srv/projects/demo \
  --name mac-mini-01
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo install -m 600 /dev/null /etc/mobile-testing/runner.env
sudo tee /etc/mobile-testing/runner.env >/dev/null <<'EOF'
MOBILE_TESTING_HOST_ID=mac-mini-01
MOBILE_TESTING_RUNNER_CONTROL_URL=http://<中心地址>:8765
MOBILE_TESTING_RUNNER_JOB_TOKEN=<与中心相同的令牌>
AOS_RUNNER_ARTIFACT_TOKEN=<可选令牌>
# 回退直连 PG 时改为：MOBILE_TESTING_DATABASE_URL=postgres://aos:<密码>@<中心PG>:5432/mobile-testing
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now mobile-testing-runner
```

### 2.7 验收

1. 中心能查到主机：

```bash
node dist/cli.js host show mac-mini-01
```

2. 面板 `GET /panel?section=runners` 显示「执行机在线」，设备容量与队列正常。
3. 面板 `GET /panel?section=devices` 能看到本机设备，状态为空闲。
4. 创建一个指向该主机的任务：

```bash
node dist/cli.js suite task create \
  --host mac-mini-01 \
  --project /srv/projects/demo \
  --ref <featureKey> \
  --platform android
```

5. 观察任务从 `pending → claimed → running → completed/partial/failed`，并在面板任务页看到运行结果与产物链接。
6. 若任务一直 `pending`，按第 6 节排查。

## 3. 流程 B：把空闲机器接成 Web 执行机（`web-runner`，已移除）

> **2026-11-06 已移除**：以下流程仅作历史参考，命令不再可用。Android 真机请用 [android-mcp-native-testing.md](./android-mcp-native-testing.md) 的 adb-host。

适用：机器不参与项目源码开发，只作为设备池执行「托管 Web 项目」下发的 Maestro 任务。

### 3.1 中心侧准备

1. 中心以 HTTP 模式运行（推荐）：

```bash
export MOBILE_TESTING_DATABASE_URL='postgres://aos:<密码>@<中心PG>:5432/mobile-testing'
export MOBILE_TESTING_RUNNER_JOB_TOKEN='<至少16字符的随机串>'
# 非 loopback 部署必须配置鉴权，否则启动直接 exit 2
export MOBILE_TESTING_HTTP_TOKEN='<面板/管理令牌>'
node dist/cli.js serve --http --host 0.0.0.0 --port 8765 --workspace /srv/aos-workspace
```

> `serve --http` 默认只监听 `127.0.0.1`；要让其他机器上的 `web-runner` 连进来，必须显式 `--host 0.0.0.0`（或指定网卡地址）。绑定非 loopback 且未配置 `MOBILE_TESTING_HTTP_TOKEN`/命名用户时，服务会拒绝启动并 `exit 2`；`AOS_HTTP_ALLOW_INSECURE=1` 只是受控内网的显式逃生门。

2. 确认中心暴露控制面与 job 数据面路由（这些接口由 `serve --http` 提供，独立 `panel --web` 不提供）：

   - `POST /panel/api/runners/*`（心跳 / 领取 / 租约 / 任务生命周期 / stop）
   - `GET /panel/api/jobs/:id/spec`
   - `GET /panel/api/jobs/:id/assets/:assetId`
   - `POST /panel/api/jobs/:id/results`

3. `MOBILE_TESTING_RUNNER_JOB_TOKEN` 在**中心与执行机配置同一个值**，至少 16 字符；更推荐中心配置 `AOS_RUNNER_HOST_TOKENS=[{hostId,token}]`，执行机使用自己那一条，`X-AOS-Host-Id` 必须与 token 所属主机一致（否则 403）。该令牌用于控制面与 job 数据面，不会回退管理员令牌，也不放行其他路径。
4. 在面板创建「托管 Web 项目」，并上传 Excel/CSV、安装包、脚本 zip 等资产；否则没有可下发的任务。

> runner 路由使用独立的 `MOBILE_TESTING_RUNNER_JOB_TOKEN`，与面板的 `MOBILE_TESTING_HTTP_TOKEN` / 用户令牌相互独立。若前面还有反向代理，记得放行 `/panel/api/runners/*` 与三条 job 路径，并保留 `Authorization` 与 `X-AOS-Host-Id` 请求头。

### 3.2 执行机准备

1. 部署代码并构建：

```bash
git clone --recurse-submodules <仓库地址> /opt/AOS-Artemis
cd /opt/AOS-Artemis
npm ci
npm run build
node dist/cli.js doctor
```

2. 安装并验证设备工具：

```bash
adb devices                 # Android 真机/模拟器
maestro --version           # Maestro
xcrun simctl list devices booted   # macOS + iOS 模拟器
```

- Android 真机/模拟器、iOS 模拟器都可用于 Maestro 任务。
- **iOS 真机不支持 Maestro**：中心在下发阶段会以 `ios-maestro-requires-simulator` 拒绝；iOS 真机只能等 LLM 执行（当前未接线）。
- `maestro` 不在 PATH 时用 `AOS_MAESTRO_PATH` 指定。
- iOS 模拟器需要 macOS + Xcode；Linux/Windows 只能接 Android。

3. 准备目录与身份：

```bash
export MOBILE_TESTING_HOST_ID=web-mac-01
export AOS_RUNNER_WORK_DIR="$HOME/.aos/web-runner"   # 默认值
export AOS_RUNNER_CACHE_DIR="$HOME/.aos/web-runner/cache"
```

`web-runner` 是 host 级进程，**不需要项目目录**；`MOBILE_TESTING_HOST_ID` 仍然必须集群内唯一。

### 3.3 首次启动

```bash
export MOBILE_TESTING_HOST_ID=web-mac-01
export MOBILE_TESTING_RUNNER_CONTROL_URL='http://<中心地址>:8765'
export MOBILE_TESTING_PANEL_BASE_URL='http://<中心地址>:8765'   # 可省略，默认回退控制面
export MOBILE_TESTING_RUNNER_JOB_TOKEN='<与中心相同的令牌>'

node dist/cli.js web-runner \
  --name web-mac-01 \
  --control-url "$MOBILE_TESTING_RUNNER_CONTROL_URL" \
  --once
```

> 如果暂未启用控制面，可删掉 `MOBILE_TESTING_RUNNER_CONTROL_URL`/`--control-url`，改为设置 `MOBILE_TESTING_DATABASE_URL` 走直连 PG 兼容路径。

说明：

- `--once` 只跑一轮：心跳/选机 + 每台设备一次领取并执行一次尝试，然后退出。适合首次验收；有 pending 任务时会真的执行。
- 缺中心基址（`--panel-base-url`/`MOBILE_TESTING_PANEL_BASE_URL`，或控制面回退）或 `MOBILE_TESTING_RUNNER_JOB_TOKEN` 不足 16 字符时，启动即 `exit 2`，不会静默降级。
- 配置控制面后不再要求 `MOBILE_TESTING_DATABASE_URL`；启动日志会打印 `控制面 http://...`。
- 设备按「每台设备一个 worker」并行；同一 serial 同一时刻只执行一个 job，靠设备租约保证。
- 启动后会 upsert 主机心跳（`runnerSeenAt`），因此面板能立即看到执行机在线。

### 3.4 验收

1. 中心主机视图：

```bash
node dist/cli.js host show web-mac-01
```

2. 面板 `GET /panel?section=runners` 显示执行机在线；`GET /panel?section=devices` 显示设备、平台、型号、系统版本与空闲/占用状态。
3. 在面板 `GET /panel?section=jobs` 下发一个网页测试任务：
   - 自动选机：中心按平台、设备形态、工具、型号/系统偏好选择空闲执行机并预占设备；
   - 手动指定：选择目标主机，可进一步钉住 serial；
   - 若手动指定的主机离线，任务会保持 pending 并保留意图，不会假装执行。
4. 任务进入 `claimed → running`，执行机完成「拉 spec → 下载资产（sha256 校验）→ 安装 → Maestro → 上传结果」；面板任务详情看到逐用例结果与 Excel 写回状态。
5. 结果状态口径：执行器上报 `passed|failed|partial|error`；`error` 在中心落 `taskStatus:"error"` / `dbStatus:"failed"`，不会在上传层被降级成 `failed`。

### 3.6 Web 执行机的能力边界

- 支持：Android 真机/模拟器、iOS 模拟器（Maestro）。
- 不支持：iOS 真机的 Maestro 执行；`executionMode:"llm"` 当前返回 `llm-execution-not-wired`。
- 设备范围由心跳上报；设备消失、状态不可用、被其他任务租用会在选机阶段被硬过滤。工具检查只在任务显式声明 `requirements.tools` 时生效；未声明时不会在选机阶段拦截，执行阶段才可能因缺少 Maestro 而失败。
- 任务重试上限：`jobSpec.retry>0` 时为 `retry+1`，否则 `AOS_RUNNER_MAX_ATTEMPTS`（默认 3）；达上限写 `failed` 并停止回池。
- 工作目录：`<workRoot>/<projectSlug>/<jobId>`；资产按 sha256 缓存；`secret:true` 的 materials 只落 `secrets/`（0600，不进缓存）。
- 执行超时：`AOS_WEB_JOB_TIMEOUT_MS`（默认 900000ms，即 15 分钟）。
- 失联回收：`MOBILE_TESTING_RUNNER_STALE_CLAIM_MS`（默认 900000ms，即 15 分钟；`0` 关闭时间判定）。

## 4. 队列与设备租约

### 4.1 队列暂停/恢复

暂停是**整机级**闸门，只阻断 runner 自动领取，不影响已领取/执行中的任务，也不阻断手动执行。

```bash
# 查看
node dist/cli.js suite queue status --host mac-mini-01

# 暂停（可写备注进审计）
node dist/cli.js suite queue pause --host mac-mini-01 --note "维护窗口"

# 恢复
node dist/cli.js suite queue resume --host mac-mini-01
```

Web job 的选机与回池同样会跳过 `queuePaused` 的主机。

### 4.2 设备租约

- 租约主键是 `(host_id, serial)`；同一台设备同一时刻只能被一个任务占用。
- 项目机与 Web 执行机共用同一套设备租约。
- 租约 TTL 由 `AOS_DEVICE_LEASE_MS` 控制（默认 90000ms，即 90 秒），续租周期为 TTL/3。
- 执行期间不要强杀 runner 进程；优雅退出（SIGINT/TERM）会把实例标记为陈旧，下一次启动可立即接管。崩溃后不是只等 90 秒在线 TTL：还要等 `MOBILE_TESTING_RUNNER_STALE_CLAIM_MS`（默认 15 分钟）窗口，并由**在线 runner**执行回收；`AOS_RUNNER_TTL_MS`（90 秒）只用于判定执行机离线。
- 手动 `suite run --task` 也会占用设备租约；冲突时 `exit 2`，需要等待或释放。

### 4.3 失联与救济

- 项目机 runner 每轮自动回收「超龄 + 领取机失联」的任务（`MOBILE_TESTING_RUNNER_STALE_CLAIM_MS`，默认 15 分钟；项目机设 `0` 会**完全关闭**失联回收，不是只关闭时间条件）。
- Web job 失联由在线 runner 的 `recoverStaleWebJobs` 回收；队列暂停期间不改派。
- 回收动作由**在线 runner**执行：全集群一台 runner 都不在线时没人回收，先恢复任意一台在线 runner，再等下一轮或手动 `release`。
- 机器报废、长期离线等场景：

```bash
node dist/cli.js suite task release <taskId> --project <rootPath> [--force]
```

> `suite task release` 在项目作用域内执行；在中心或其他目录运行时必须显式给 `--project`（与任务所属项目根路径一致），否则会找不到任务。

## 5. 日常运维

### 5.1 升级执行机

1. 先升级中心 PG（任一进程正常启动会执行幂等迁移；首次升级选低峰窗口）。
2. 在每台执行机上停止 runner 服务。
3. 拉取新代码、`npm ci && npm run build`；项目机再跑 `node dist/cli.js doctor --install-deps`。
4. 如果是旧版单机数据迁移，先做 `host adopt-legacy --local --dry-run/--apply`，再启动新版 runner。
5. 启动服务，确认心跳、设备清单、版本正常。
6. 中心与所有执行机版本一致后，再考虑打开 `AOS_HOST_STRICT=1` 等收紧开关。

### 5.2 扩容

- 项目机：一台机器可以跑多个项目的 runner（每个进程一个 `--project`、唯一的 `--name`），但设备租约是主机级，多个项目会争用同一批设备；按项目/设备池规划。
- Web 执行机：一台主机只能有一个 `web-runner`（`web_runners.host_id` 唯一）；扩容加机器，不要在同一主机双开。
- 新增机器必须使用新的 `MOBILE_TESTING_HOST_ID`；主机名相同不构成冲突，身份以 `MOBILE_TESTING_HOST_ID` 为准。

### 5.3 下线

1. 先暂停该主机队列，等待已领取任务结束。
2. 停止服务（SIGINT/TERM），确认没有 running 任务。
3. 把该主机上的未完成任务 `release` 或等待失联回收。
4. 如不再使用，清理该机工作目录与设备连接；主机登记目前没有 CLI 删除命令，离线后保留在面板即可，不要为了“加速”下线直接删除 PG 行（会破坏项目、任务与租约的引用）。

## 6. 排障速查

| 现象 | 优先检查 | 处理 |
|---|---|---|
| `host` / `suite queue --host` 命令 `exit 2` | 是否设置 `MOBILE_TESTING_DATABASE_URL` | 这两类命令只支持中心 PG，不回落文件台账；本地 `suite queue`（不带 `--host`）仍可用项目台账 |
| web-runner 启动提示需要 PG | 是否设置 `MOBILE_TESTING_RUNNER_CONTROL_URL`/`--control-url` | 两者都没配时才回退 PG；控制面模式不需要 `MOBILE_TESTING_DATABASE_URL` |
| 面板看不到新机器 | runner 是否启动、PG 是否可达、心跳是否报错 | 看服务日志；`host list` 是否出现；检查防火墙与连接串 |
| 主机反复上下线 | 两台机器是否共用 `MOBILE_TESTING_HOST_ID` / `host-id` | 给每台机器设置唯一 `MOBILE_TESTING_HOST_ID`，清理复制的 `~/.aos/host-id` |
| 主机在线但没有设备 | `adb devices` 是否 `unauthorized`；模拟器是否 Booted；真机是否被自动盘点遗漏 | 授权设备、启动模拟器、用 `AOS_RUNNER_DEVICES` 补录 |
| 任务一直 `pending`（项目机） | 队列是否暂停；任务端是否 ⊆ 本机设备端；项目是否登记；`--project` 是否正确 | `suite queue status`；`host show`；补设备或拆单端任务；确认项目行 |
| 任务一直 `pending`（Web） | 是否有在线 `web-runner`；平台/设备形态/工具是否匹配；设备是否被租用；主机是否暂停 | 面板 runners/devices；`MOBILE_TESTING_RUNNER_JOB_TOKEN`；等待租约释放 |
| Web runner 启动即 `exit 2` | `MOBILE_TESTING_PANEL_BASE_URL` 是否设置；`MOBILE_TESTING_RUNNER_JOB_TOKEN` 是否 ≥16；PG 是否可达 | 补齐环境变量；中心与执行机令牌保持一致 |
| spec/资产/结果接口 401 / 503 | 401＝Bearer 缺失或错误；503＝中心未配置 token 或 token 不足 16 字符 | 中心与执行机设置同一个 `MOBILE_TESTING_RUNNER_JOB_TOKEN`（≥16） |
| spec/资产/结果接口 403 | `X-AOS-Host-Id` 与 job 的领取/目标主机不一致 | 检查任务是否被其他主机领取；不要手工伪造 host 头 |
| 产物链接 401 | 设置了 `AOS_RUNNER_ARTIFACT_TOKEN`，浏览器未输入 | 在弹窗输入令牌；或临时关闭令牌（仅内网） |
| `adopt-legacy` 提示「跳过」 | 同路径新项目行已存在 | 迁移顺序错了；legacy 行保留归档，人工核对后处理 |
| 手动执行报「设备被占用」 | 设备租约被 runner 或其他进程持有 | 等待任务结束；确认没有双开 runner；必要时释放租约 |
| 任务执行超时/卡住 | 设备是否响应；`AOS_TASK_MAX_RUNTIME_MS`；Web 的 `AOS_WEB_JOB_TIMEOUT_MS` | 看任务日志与设备状态；超时会被标记取消/失败，不会假绿 |

## 7. 安全基线

1. **服务级密钥**：`MOBILE_TESTING_DATABASE_URL`、`MOBILE_TESTING_RUNNER_JOB_TOKEN`、`AOS_RUNNER_ARTIFACT_TOKEN` 放在服务管理器环境文件（0600）中，不要提交仓库，不要放进项目 `.env` 充当中心配置。
2. **避免命令行泄露**：不要把令牌写进 `ExecStart`/命令行参数（`ps` 可见）；用 `EnvironmentFile` 或 launchd `EnvironmentVariables`。
3. **数据库**：中心 PG 不要直接暴露公网；用 VPN/SSH 隧道/安全组限制来源。
4. **数据库权限**：未配置控制面的项目机/web-runner 连接串拥有中心台账写权限，且打开 store 会执行幂等迁移；不要授予超级用户，限制来源地址并定期轮换。项目机/Web 执行机优先使用控制面模式，避免分发 DB 凭证。
5. **产物服务**：默认监听 `0.0.0.0` 且无鉴权；生产必须限制网段或设置 `AOS_RUNNER_ARTIFACT_TOKEN`，不需要时 `--artifact-port 0` 关闭。
6. **中心 HTTP**：非 loopback 部署必须设置 `MOBILE_TESTING_HTTP_TOKEN` 或用户令牌，否则服务拒绝启动并 `exit 2`；`AOS_HTTP_ALLOW_INSECURE=1` 只是受控内网的显式逃生门，不能当作生产方案。
7. **HTTPS/mTLS**（OCSP 需前置代理，示例见 [tls-mtls-proxy.md](./tls-mtls-proxy.md)）：中心设置 `AOS_HTTP_TLS_CERT`/`KEY` 启用 HTTPS；mTLS 再加 `AOS_HTTP_TLS_CA` + `AOS_HTTP_MTLS=1`。执行机设置 `AOS_RUNNER_TLS_CA`（mTLS 加 `CERT`/`KEY`），控制面地址改为 `https://`。
7. **最小权限**：runner 以专用用户运行，只授予项目目录、设备与工作目录权限；不要用 root 常驻。
8. **日志**：服务日志只输出 masked 预览；不要把密钥、完整 token 写进 issue 或聊天记录。
