## 1. 能力总览

一个 **MCP 服务进程**，把四类能力合并到一个端点，供任意 MCP 客户端（Claude Code / Cursor / VS Code / opencode / Codex）调用：

| 能力 | 实现 | 外部依赖 |
|---|---|---|
| Figma 设计上下文 | 内嵌 design-context-bridge（vendor 20 工具）+ 5 个原生流水线工具 + 2 个 M6 可选工具 | 插件桥需 Figma 打开文件；REST 需 `FIGMA_ACCESS_TOKEN` |
| pen.dev 设计接入 | 离线合成/解析（`pen_inspect`/`pen_extract_flows`/`pen_import_*`/`pen_export_brief`）+ 托管 pen CLI（导出/写回/agent） | 离线工具零依赖；CLI 工具需 `PEN_CLI_KEY`（或 `pen login`）+ 网络 |
| ARTEMIS 移动自动化 | Python 子进程 `python -m mcp_server`，`mobile_*` 5 工具 **schema 原样透传**（iOS 模拟器/真机由 AOS 后端接管） | 已授权 Android 设备/模拟器 或 iOS 模拟器/真机 + artemis venv |
| 项目级 LLM 关联与切换 | PostgreSQL（可降级内存）+ 项目 `.env` 首扫导入 | PG 可选；LLM key 必填（执行任务） |

闭环总览（"设计 → 用例 → 执行 → 证据 → 反馈 → 完善"）：

```mermaid
flowchart LR
  A["Figma / .pen 设计"] --> B["flows / flow-map / gaps / tokens / strings / brief"]
  B --> C["tests.json + md + xlsx<br/>caseId + 前置假设 + taskDesc"]
  C --> D["suite check（静态覆盖，CI 前置）"]
  D --> E["suite run / mobile_run_task（真机执行）"]
  E --> F["台账 + .artemis/traces + 崩溃签名 + API 错误"]
  E --> G["suite calibrate（xcresult 差分校准）"]
  F --> H["suite report（xlsx + JUnit + 追溯矩阵）"]
  F --> I["suite feedback → suite loop（下一步动作）→ 回到 B/C"]
```

## 2. 运行逻辑

### 2.1 进程入口与两种传输

- `dist/index.js` → `serve`（`src/cli.ts`）
- **stdio 模式（默认）**：`runServer()`（`src/server.ts`）启动顺序：
  1. `loadProject()` 解析项目身份
  2. `createProjectStore()`：PG；不可用则降级会话内存并告警
  3. `new Runtime(...)` + `runtime.initialize()`
  4. 配置日志与崩溃钩子、`sweepStaleChild()` 清理上次残留的孤儿 `mcp_server` 进程
  5. 启动 Figma 插件桥（**端口锁定 3055**；被占用记 `skipped_occupied`，不做文件共享）
  6. 启动后台 **30s 循环**：把 `submitted` 任务轮询到终态 → 回写台账 → 触发崩溃采集
  7. 进入 MCP 消息循环
- **HTTP 模式**：`serve --http --port 8765 --workspace <dir>`
  - 端点 `POST /mcp/<project>`，健康检查 `GET /healthz`
  - workspace 下每个子目录是一个项目，**各自独立 Runtime**（LLM 关联/子进程/台账互不影响）；项目名限 `[A-Za-z0-9._-]`
  - 与 stdio 共用 `createServerForRuntime()`，工具面完全一致

硬性约定：**stdout 属于 MCP stdio 协议**；日志走 `log()`（stderr）与文件；CLI 子命令输出除外。

### 2.2 项目身份解析

优先级（`src/config/loader.ts`）：

```text
AOS_CONFIG（显式配置文件） > AOS_PROJECT_DIR > 从 cwd 向上找 aos.config.jsonc > cwd 兜底
```

- 配置目录默认 `<项目根>/.artemis/`
- `aos.config.jsonc` 是**可选高级层**（多 LLM 档案、artemis 指向等），不配置也能运行
- 服务仓库与被接入项目相互独立：产物全部落**被接入项目**的 `.artemis/`

### 2.3 每个项目的 Runtime 装配

| 成员 | 作用 |
|---|---|
| `store` | PG / 内存台账（`projects`、`project_llms`、`task_stats`、`llm_model_cache`、`usage_events`） |
| `state` | `.artemis/state.json`：active 条目、子进程 pid/fingerprint（跨启动复用） |
| `crashStore` / `crashScanner` | 崩溃签名索引 + 终态自动采集 |
| `modelCatalog` | 厂商 `/models` 缓存与模型下线自动修复 |
| `proxy` | ARTEMIS 子进程代理（外层包 artifact mirror 与 iOS 路由） |
| `scanResult` | 项目 `.env` 首次扫描结果 |

`initialize()`：注册项目 → `.env` LLM 首扫导入 PG（仅当尚无条目）→ active 物化为 `.artemis/artemis.jsonc` → 导入 `.env` 的 Figma token。

### 2.4 LLM 条目与切换语义

- 条目优先级：**store(PG) > `aos.config.jsonc` profiles > 环境变量**
- env 兼容：`AOS_LLM_MODEL/BASE_URL/API_KEY` 优先，兼容 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `OPENAI_BASE_URL`
- 缺项 → 工具返回 `setup_required`，用 `aos_configure` 补全（写 PG + 项目 `.env`）；`vendor` 一键配置 8 家国产厂商（deepseek/qwen/zhipu/moonshot/siliconflow/stepfun/ark/hunyuan）
- **切换语义**（`llm_switch`）：改 model → 下个任务生效；改 provider/key/base_url → 重启 ARTEMIS 网关子进程（只杀直接子进程，detached 任务不动；运行中任务被守卫拦截，`force:true` 跳过）
- 模型目录：定时 `GET {baseUrl}/models` 缓存（`AOS_MODEL_REFRESH_HOURS` 默认 12h，0 关闭）；模型下线自动修复（别名/同族等价，capability 不降级；`AOS_LLM_AUTO_REPAIR=0` 关闭）+ `mobile_run_task` 预检拦截
- artemis 统一走 OpenAI 兼容 `custom` provider；非 Google provider 自动覆盖钉死的 `object_detector`/`hopper` 节点（附精度警告）

### 2.5 ARTEMIS 子进程与 `mobile_*` 透传

- 装配（`src/artemis/assembly.ts`）：生成 child spec（`python -m mcp_server`），注入 active LLM 凭证、`ARTEMIS_TRACES_DIR=<项目>/.artemis/traces`、锁定应用包；每次（重）启动重新生成 env/fingerprint
- 代理（`src/artemis/proxy.ts`）：惰性启动；`listTools` 缓存；`callTool` **逐字转发**；不做 zod 镜像
- iOS 接管：`device_serial` 为模拟器 UDID 时由 AOS iOS 后端（idb/simctl）执行；真机 UDID 走 Appium+WDA（见 §3.7）
- 结果镜像：`mobile_get_device_state` 实时截图自动复制到 `.artemis/traces/live_screenshots/`
- 子进程 stderr 落 `.artemis/logs/artemis-child.log`

### 2.6 任务生命周期（`mobile_run_task` 之后）

```text
提交
 ├─ task_stats 记 submitted；caseId 用 taskDesc 精确匹配 tests.json 回填
 ├─ 即时报错：直接记 failed 终态（无 trace 用 local-<uuid> 占位）
轮询（后台 30s 循环 / aos_tasks 手动 sync / CLI suite 自己轮询）
终态
 ├─ markTaskFinished（写 finished_at）
 ├─ 触发崩溃采集 → 签名去重（包名 + 根因异常 + 首个应用帧）→ .artemis/crashes/
 └─ 产物：.artemis/traces/<traceId>/（步骤截图、notes、stdout/stderr、data_engine.db）
```

### 2.7 设计流水线与流程完整性契约

**Figma 五工具（原生）**：

```text
figma_extract_flows      → flows.json（screens/edges/entryScreens + warnings）
figma_gap_analysis       → gaps.json（按技术栈选扫描规则/命名/目录）
figma_generate_tests     → tests.json/md/xlsx（稳定 caseId、preconditions、可直接执行的 taskDesc）
figma_import_assets      → 按栈命名+目录幂等写入；PNG 默认倍率集
figma_export_brief       → build-brief.json/md（可 scaffold 组件骨架）
figma_import_tokens      →（M6 可选）颜色 token → tokens.json + 栈文件
figma_import_strings     →（M6 可选）文案 → strings.json + 五栈资源
```

**pen 工具**：离线 `pen_inspect` / `pen_extract_flows` / `pen_import_tokens` / `pen_import_strings` / `pen_export_brief`；CLI（需 pen CLI）`pen_export` / `pen_apply_tokens` / `pen_apply_strings` / `pen_agent`。

**流程完整性三闸（DESIGN §6.10）**：

| 闸 | 工具 | 保证 |
|---|---|---|
| 提取闸 | `figma_extract_flows` | `warnings` 显式报告 `no-entry` / `unreachable-screens` / `unresolved-destinations` / `no-interactions`（屏幕>1 且零跳转） |
| 生成闸 | `figma_generate_tests` | 响应与 tests.json 写 `coverage`（**硬覆盖**：未覆盖屏幕/跳转、截断、entryFallback；`explore` 报告 inferred 缺口不阻断）；**`requireFullCoverage:true` 时硬覆盖不完整即报错、三份都不落盘** |
| 执行闸 | `suite run --fail-on-uncovered` | 未硬覆盖/截断/缺 flows（fail-closed）→ exit 2（探索缺口仅报告；`--strict` 加弱断言门禁）；自定义 `--tests` 同样校验 |

**生成策略**：覆盖贪心 + 长路径优先——先选覆盖增量最大的连续路径，同增量取更长者；无新增覆盖的冗余短片段不产出；`maxDepth` 默认 30（可配，上限 50），单条用例的边数上限；达到上限不丢尾——以截断屏为起点生成首尾相接的续段用例（覆盖仍完整，`generation.depthSplits` 报告接续条数），长流程调大即可生成更长连续用例。

**续段自包含 + 步骤断言**：续段用例自带"入口 → 切点"的前导导航（`prelude`，taskDesc 中「前导导航（仅到达起点，不计断言）」段，`continuation/startScreen` 字段标注），可独立执行、不依赖上一段状态。每步断言以 `expectations`（目标屏+hints）结构化输出，并随 taskDesc 附 `【AOS-EXPECT】` JSON 块；iOS 执行器逐步确定性核对，命中记 step `scriptHits`，汇总 `test_summary.adherence`（`checkable/satisfied/unresolved`）；未出现项进入终态验证证据与摘要 `⚠` 行。块内 `start`（入口屏+hints）由执行器首步核对（preflight）：未命中每步注入导航提示并记 `test_summary.preflight`（同样建议级）。Android 侧忽略该行。

**pen 合成提取**（`pen_extract_flows`，离线）：`.pen` 无原型交互数据时——屏幕命名取「Flow 标注 > 屏内首个文本 > 图层名」；状态变体按标签前缀归并为主屏 + `states`；跳转按画板序号/画布排布推断（统一 `INFERRED`，需复核）；产出 `flows.json` + 全局 `flow-map.md` + 碎片度 warnings。检测到交互线索（text `href`/交互类键/metadata）时显式标注 `pen-interactions-present`（当前未解析、仍按画板推断，不静默）。

**设计版本锚点**：`figma_extract_flows` 将 Figma `version`/`lastModified` 写入 flows.json（`fileVersion`/`lastModified`），为设计冻结预留。

### 2.8 测试闭环（CLI `suite`）

```bash
# 静态（不连设备，CI pre-merge 用）
node dist/cli.js suite check [--tests <path>] [--json]
#   覆盖完整 exit 0；未覆盖/截断/缺 flows exit 2；输出"路线漂移"警告（测试引用但设计缺失）

# 执行（连设备）
node dist/cli.js suite run [--tests <path>] [--max N] [--stop-on-failure]
                           [--device <serial>] [--app <pkg>] [--model Flash|Pro]
                           [--no-api-errors] [--fail-on api-error] [--fail-on-uncovered] [--retry N]

# 差分校准（确定性套件 vs MCP 台账）
node dist/cli.js suite calibrate (--report <json|junit.xml>|--xcresult <bundle>) [--tests <path>] [--fail-on-miss]
#   测试名需内嵌 case_id（如 test_order_flow_case-<12hex>()）；JUnit XML 直读（Android instrumentation 可用）；输出漏报率/误报率并落盘

# 一步闭环（检查→执行→反馈→校准合并）
node dist/cli.js suite loop [--skip-run] [--calibration <json>] [--retry N] [--allow-uncovered]
#   产出 loop-<stamp>.{json,md}：步骤结果 + 确定性"下一步动作" + top 建议

# 重复采样（执行确定性量化；不依赖项目接线）
node dist/cli.js suite flake --cases <id,id,...> [--runs N] [--fail-on-flaky]
#   通过率/翻转矩阵/flaky 率 → flake-<stamp>.{json,md}；翻转率决定 L2 投入强度，不决定其存废

# 审计保留期（只读，不删除）
node dist/cli.js suite retention [--days 90] [--limit 20]
#   五类产物（reports/evidence/diffs/traces/crashes）超期统计与最旧项；清理待合规口径

# 证据/回归/报告/反馈
node dist/cli.js suite evidence <traceId> [--full-trace]
node dist/cli.js suite api-errors <traceId>
node dist/cli.js suite baseline save|compare --case <id> --step <n> --trace <id> [--fail-on new|persisting|any]
node dist/cli.js suite report [--limit N] [--case <id>]...   # xlsx + JUnit + 追溯矩阵工作表
node dist/cli.js suite feedback [--min-failures N]           # 生成改进建议（只读）
```

- 失败域（确定性规则）：应用缺陷（崩溃签名）/ 环境（设备/adb）/ API 错误（未处理）/ 数据环境（命中前置假设）/ 设计推断（纯探索或断言全命中而探索未达成）/ 行为或设计差异 / 用例缺陷 / 未分类
- API 错误：注册表 `.artemis/design/error-codes.json`（`{codes:{"<code>":{match,handler?,expect?,handledPattern?}}}`）；`run` 默认逐例采集，`--fail-on api-error` 把未处理错误判 FAIL
- **退出码**：`0` 全通过；`1` 用例失败或证据缺失；`2` 参数/执行错误或 `--fail-on*` 命中（含流程未覆盖/无法校验、校准漏报）
- `--retry N`（≤3）：仅对未通过用例重跑做 **flake 诊断**并如实标注 `retry{attempts,finalStatus,finalTraceId,flaky}`；**首跑结果仍决定门禁**（重跑转绿不计）
- `flake`（采样）：指定 3–5 条代表用例 × N 轮重复执行，输出逐例通过率、翻转矩阵与 flaky 判定（口径见 DESIGN §6.10）；`--fail-on-flaky` 可门禁
- `quarantine`：`.artemis/design/quarantine.json` 生效项仍执行并标注，**失败不计门禁**（owner 签字，可选到期自动恢复）；`--no-quarantine` 严格审计跑
- 公共选项：`--project <dir>`、`--json`
- **CI 建议双轨**：pre-merge 跑 `suite check`（秒级、不连设备）；nightly 跑 `suite run --fail-on-uncovered` + `suite calibrate` + `suite report`，次日看审计产物

### 2.9 确定性差异与基线

- `design_device_diff`：设计源 Figma 节点或 `.pen`（pen CLI 渲染）vs 设备截图（`live` 实时 / `step` 失败步骤截图）；对齐（insets/ignoreRegions/降采样）→ 像素差异 + 设计节点几何分类（`missing/extra/text/asset/position-size/color`）→ 报告 + 标注图，落 `.artemis/design/diffs/`；判定不依赖 LLM
- `suite baseline`：设备对设备像素回归（last-known-good），按设备分桶；分辨率/DPI 不符记 `unmapped` 不比对

### 2.10 存储 / 日志 / 安全

- PG 表：`projects`、`project_llms`、`task_stats`、`llm_model_cache`、`usage_events`；无 `MOBILE_TESTING_DATABASE_URL` 时降级内存（`aos_status` 警告，重启丢台账）
- 日志：`.artemis/logs/aos-mcp.log`（工具调用审计 + `usage=<id>` 互链）、`artemis-child.log`；`AOS_LOG_LEVEL/DIR/DISABLE_FILE/MAX_MB` 可调
- 使用统计：客户端每次工具调用记一条（不带参数值）；`aos_usage` / `usage` CLI / HTTP `/usage` 三面同源
- 密钥只存项目 `.env`（或按产品要求 PG）；工具响应只回 masked 预览；日志不落 key

### 2.11 统一服务四入口（对话层）

四个一等流程工具把"设计→用例→设备→报告/回写"收进服务内部（不 shell 到 CLI/脚本；执行统一复用 `executeSuiteBatch`＝quarantine＋批次清单＋`suite_runs` 登记）：

- `design_to_test`：设计稿（`figmaUrl`/`penPath`）→ 出用例（三件套）→ 静态校验；`run` 缺省 false 止于校验，响应含 `nextAction` 续跑（`reuseExistingFlows:true`）。
- `run_regression`：Excel 测试文档（`excelPath`）导入用例库后执行；或按 `scope`（功能/用例名，归一化匹配）选库内最新份；`all`/缺省跑每功能最新份全量。导入集覆盖闸标注 `n/a (imported)`；执行前回显功能×条数与来源。
- `verify_jira_issue`：Jira 单（`issueKey`）读单分档——详细单走用例库映射（LLM 只能从清单中选或答没有）或「单子即用例」；粗单先问。聚合：任一强断言失败→FAIL，全弱/全探索→无法判定（弱断言仅记录路径）；回写失败证据＋结论评论（marker `AOS-VERIFY:<单号>` 幂等复用；不写 verdict、只关联 `jira_issue_key`）；`dryRun` 零写回。
- `project_archive`：只读摘要（项目与栈/设计血统/用例库/最近运行/裁决与 Jira/前置状态）；不触网·无子进程·不写盘；恒 `ok:true`＋`degraded[]`（PG 不可用降级内存时显式提示）。

**前置与提问协议**：执行类调用先自查（LLM 连通性 ping、Figma/pen/Jira 凭据、在线设备）；`project_archive` 仅静态存在性并显式「未复核」。缺失→非错误 `needs-setup`（`checks[]` 每项 target/missing/howTo）；信息不足→`needs-info`（questions/context＋`category`：`device-ambiguous`/`no-flows`/`scope-no-hit`/`library-empty`/`ticket-coarse`）。单步失败→`{failedStep, detail, suggestions}`。

**使用统计信号（D12）**：`needs:<target>`（+`needs:<target>.missing`）、`needs:info.category`、`failed-step:<step>`、`step-ms:<step>`、`import.outcome`、`scope.match`、`run.gate`、`ticket.detailTier`、`mapping.selected|none`、`writeback`。

详见 README 工具表与 DESIGN §13.119–§13.123。

## 3. 项目接入（详细步骤）

### 3.0 接入总览（照抄执行）

先约定读法：**CLI 命令**在服务仓库（AOS-Artemis）目录执行；**工具**（`aos_status`、`aos_configure`、`figma_extract_flows`…）是 MCP 工具，在客户端对话里调用。

```text
① 部署服务本体     → 克隆 + 构建 + doctor --install-deps（一次）
② 配置目标项目     → 填 .env（至少 LLM 三键）→ doctor 验证
③ 挂载到客户端     → install（或手动片段）→ 重启客户端 → aos_status 确认 setup
④ 接入设计源       → Figma token 或 .pen（先跑提取，复核 flow-map 质量）
⑤ 生成并静态校验   → figma_generate_tests(requireFullCoverage=true) → suite check
⑥ 连设备跑一轮     → mobile_diagnose → suite run（或 suite loop）
⑦ 长期化（可选）   → 中心 PG + 项目机 runner + 定时回归（§3.6、README「项目机 runner」）
```

### 3.1 部署服务本体

```bash
git clone --recurse-submodules https://github.com/louislucney/AOS-Artemis.git
cd AOS-Artemis
npm install && npm run build             # Node ≥ 20（pen CLI 自动安装需 ≥ 22.19）
node dist/cli.js doctor --install-deps   # 首次：装 artemis venv 等依赖
```

- **两种部署方式，装好后在选择客户端挂载方式时决定**：stdio＝本机单项目（最简单）；HTTP＝一台常驻、多项目共用。
- Submodule 没拉全（doctor 报 artemis 缺失）：`git submodule update --init --recursive`。
- 目标机不能联网：先在能联网的机器 `node dist/cli.js deps build`，把 `dist-deps/artemis-deps-<os>-<arch>.tar.gz`（＋`.sha256`）拷过去，配 `AOS_ARTEMIS_DEPS_URL` 离线秒装（见 README）。

### 3.2 配置目标项目（怎么配、配到哪）

配置只放三个地方，先记这张"放哪"表：

| 放哪 | 装什么 | 优先级 |
|---|---|---|
| 项目 `aos.config.jsonc` | 可选高级项（远程设备宿主 `deviceHosts` 等，**无密钥**） | 最低 |
| 项目 `.env` | 项目自己的凭据：LLM / Figma / pen / Jira / iOS 真机签名 | 覆盖 config |
| MCP 客户端配置里的 `env`（或 serve/runner 进程 env） | 服务级配置：`AOS_PROJECT_DIR`、`MOBILE_TESTING_DATABASE_URL`、HTTP/产物令牌 | 最高 |

> **最容易配错的一条**：项目凭据放项目 `.env`；**数据库 URL（`MOBILE_TESTING_DATABASE_URL`）放客户端 env，不要写进项目 `.env`。**

**第 1 步（可选）：脚手架**。在目标项目目录执行，会写 `aos.config.jsonc`＋`.env.example` 并打印下一步：

```bash
node <AOS-Artemis>/dist/cli.js init
```

**第 2 步：最小可跑配置**。复制 `.env.example` 为 `.env`，至少填 LLM 三键（其余按需）：

```bash
# <目标项目>/.env
AOS_LLM_MODEL=deepseek-flash
AOS_LLM_BASE_URL=https://api.deepseek.com/v1
AOS_LLM_API_KEY=sk-你的key
```

老项目已有 `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `OPENAI_BASE_URL` 的可以直接沿用（优先级低于 `AOS_LLM_*`）；也可以挂载后在对话里用 `aos_configure(vendor="deepseek", apiKey="…")` 写入。

**第 3 步：配置总表**（按需逐项；左列键名可直接复制）：

| 配置项 | 写在哪 | 示例 | 什么时候需要 | 不配会怎样 |
|---|---|---|---|---|
| `AOS_LLM_MODEL`／`AOS_LLM_BASE_URL`／`AOS_LLM_API_KEY` | 项目 `.env` | `deepseek-flash`／`https://api.deepseek.com/v1`／`sk-…` | 所有执行类工具（生成/回归/Jira 验证）与 pen agent | 工具返回 `needs-setup` 并给修复指引 |
| `FIGMA_ACCESS_TOKEN` | 项目 `.env` | `figd_…` | Figma REST 读取（extract / generate / assets） | Figma 工具报缺 token（可用插件桥模式替代） |
| `PEN_CLI_KEY` | 项目 `.env` | pen.dev 组织 Developer Key | pen CLI 工具（`pen_export`／`pen_apply_*`／`pen_agent`） | 需改用 `pen login`；离线 pen 工具不受影响 |
| `JIRA_BASE_URL`／`JIRA_EMAIL`／`JIRA_API_TOKEN` | 项目 `.env`（三键一起） | `https://your-site.atlassian.net` | `jira_*`、`verify_jira_issue`、面板建单 | Jira 工具返回 `howToFix` |
| `JIRA_ISSUE_PROJECT`／`JIRA_ISSUE_TYPE`／`JIRA_ISSUE_LABELS` | 项目 `.env` | `PROJ`／`Bug`／`label1,label2` | 面板「一键建单」默认值 | 建单时需每次手填项目 |
| `MOBILE_TESTING_DATABASE_URL` | **客户端 env／serve 进程／runner 服务** | `postgres://user:pass@host:5432/mobile-testing` | 台账跨重启、回归任务、runner、定时回归、`suite backfill`、多项目面板/usage | 降级会话内存：重启丢台账；runner/定时/backfill 报"需要中心 PG"退出 |
| `AOS_PROJECT_DIR` | 客户端 env | `/path/to/<目标项目>` | stdio 模式绑定项目（`install` 会写） | 服务按客户端工作目录猜项目 |
| `ARTEMIS_ADB_PATH`（artemis 用）／`AOS_ADB_PATH`（崩溃采集用） | 客户端 env／项目 `.env` | `~/Library/Android/sdk/platform-tools/adb` | adb 不在 PATH | 也可设 `ANDROID_HOME` 或把 adb 加进 PATH |
| `AOS_IOS_XCODE_ORG_ID` | 项目 `.env` | `TEAMID`（Xcode → Settings → Accounts 可见） | iOS 真机（配套 `AOS_IOS_XCODE_SIGNING_ID`、`AOS_IOS_WDA_BUNDLE_ID`） | 真机会话无法签名 |
| `AOS_APPIUM_URL` | 项目 `.env` 或 `aos.config.jsonc` | `http://127.0.0.1:4723` | 已有 Appium 时直连 | 走托管懒启动（本机装好 appium 即可） |
| `AOS_HTTP_TOKEN`／`AOS_HTTP_ALLOW_INSECURE`／`AOS_RUNNER_ARTIFACT_TOKEN` | **仅进程 env**（serve／runner 进程） | 自定义字符串 | serve --http 暴露到非 loopback／产物服务加闸 | 非 loopback 且无令牌会拒绝启动；产物服务默认内网无鉴权 |

其余可选键（图缓存、崩溃上限、模型目录刷新、批次清单等）在 `.env.example` 里逐条带说明；完整表见 README《环境变量》。两个可选数据文件：`.artemis/design/error-codes.json`（API 错误码匹配，缺省时相关步骤如实跳过）、`.artemis/design/quarantine.json`（隔离用例白名单，失败不计门禁）。

**第 4 步：验证**。`node dist/cli.js doctor` 体检服务侧（Node/依赖/PG/pen/设备链）；挂载后在对话里 `aos_status` 看 `setup`、active LLM 与存储。

### 3.3 挂载到客户端

先选模式（`install --mode`）：

| 模式 | 用在 | 要点 |
|---|---|---|
| `local`（默认） | 本机单项目 | `install` 自动写入 `AOS_PROJECT_DIR`，并透传当前 env 里的 PG / 工具路径 |
| `docker` | 服务跑在容器 | 加 `--container <容器名>`；容器需挂载目标项目目录 |
| `http` | 一台服务多项目 | 先在服务端起 HTTP（`serve --http --port 8765 --workspace /srv/projects`），再 `install --mode http --url http://<host>:8765` |

```bash
node dist/cli.js install [--targets claude,cursor,vscode,opencode] [--force]
# 写 .mcp.json（Claude Code）/ .cursor/mcp.json / .vscode/mcp.json / opencode.json；
# Codex / Claude Desktop / Windsurf 打印手动片段（照抄进各自全局配置）
```

手动片段（stdio；等价于 `local` 模式写入的内容）：

```jsonc
{
  "mcpServers": {
    "mobile-testing": {
      "command": "node",
      "args": ["<AOS-Artemis>/dist/index.js"],
      "env": {
        "AOS_PROJECT_DIR": "<目标项目>",
        "MOBILE_TESTING_DATABASE_URL": "postgres://user:pass@host:5432/mobile-testing",
        "ARTEMIS_ADB_PATH": "~/Library/Android/sdk/platform-tools/adb"
      }
    }
  }
}
```

规则：**挂载/改配置后重启客户端**（MCP 只在客户端启动时加载）。多项目两种做法：每项目一份配置（各自 `AOS_PROJECT_DIR`），或统一走 HTTP（端点 `POST /mcp/<项目名>`，服务端 `--workspace` 扫描）；HTTP 的令牌等配置见 §3.2 总表。

### 3.4 首次接入（按顺序跑一遍）

`[CLI]`＝在服务仓库执行；`[对话]`＝在客户端对话里调用工具。失败对照 §5 排障。

```text
1. [CLI]       node dist/cli.js doctor          # 体检：依赖 / PG / pen / 设备链
2. [对话]      aos_status                        # 看 setup、active LLM、存储、iOS 后端
3. [对话]      aos_configure(vendor="deepseek")  # 或 model/baseUrl/apiKey；一次写 PG＋项目 .env
4. [CLI/对话]  设计源：Figma 在 .env 填 FIGMA_ACCESS_TOKEN；.pen 直接给路径
5. [对话]      figma_extract_flows(url) / pen_extract_flows(path)   # 先看 warnings 与 flow-map
6. [对话/CLI]  figma_generate_tests(requireFullCoverage=true) → suite check
7. [对话/CLI]  mobile_diagnose → suite run --fail-on-uncovered      # 或 suite loop 一步闭环
```

一句话版本（对话层）：设计稿走 `design_to_test`（缺省止于校验，`run:true` 才执行）；已有 Excel 用例文档走 `run_regression`。脚本化用 `node scripts/design-pipeline.mjs "<figma-url>" [--import] [--scaffold]`（生成默认 `requireFullCoverage:true`）。

### 3.5 设计源接入细则

**Figma**
- REST 模式：`.env` 写 `FIGMA_ACCESS_TOKEN`（或用 `aos_configure(figmaToken=…)`）。
- 插件桥模式：Figma 桌面打开文件 → 运行插件；桥监听 `127.0.0.1:3055`（被占用记 `skipped_occupied`）。
- 限流：访客席位 low 档可能触发多日冷却——REST 侧有界等待（`AOS_FIGMA_RETRY_MAX_WAIT_MS` 默认 60s）、按 token 冷却记忆、响应缓存（`AOS_FIGMA_CACHE_TTL_MS` 默认 10min）。

**pen.dev（离线优先，桌面非必需）**
- `.pen` 是开放 JSON；`pen_inspect` 离线校验/摘要，`pen_extract_flows` 离线合成（无需桌面、无需登录）。
- 无原型交互的 `.pen`：`pen_extract_flows` 用「Flow 标注 > 屏内文本 > 图层名」命名屏幕、归并状态、按画板推断跳转（`INFERRED`），产出 `flows.json` + `flow-map.md`——**先复核 flow-map，再生成用例**。
- 需要渲染/写回/agent（`pen_export`/`pen_apply_*`/`pen_agent`）时才需要 pen CLI：缺失自动安装到 `~/.aos/pen-cli`（Node ≥ 22.19、需网络；`AOS_PEN_NO_INSTALL=1` 关闭）；登录用 `pen login` 或项目 `.env` 的 `PEN_CLI_KEY`（自动透传、不落日志）。
- 桌面 app 只在"人工交互设计/画布操作"时需要；生产链路（解析→合成→生成→执行→出图）全部 headless。

### 3.6 测试闭环接入与 CI

```bash
# 生成（工具参数 requireFullCoverage=true 已是设计流水线脚本默认）
# 静态检查（秒级、不连设备）
node dist/cli.js suite check --json

# 执行（Android 示例）
node dist/cli.js suite run --app com.example.app --fail-on-uncovered --retry 1

# 确定性套件差分校准（可选，若项目有 XCTest 等确定性套件）
xcodebuild build-for-testing -workspace X.xcworkspace -scheme UITests -destination 'platform=iOS Simulator,name=...' 
xcodebuild test-without-building ... -resultBundlePath /tmp/x.xcresult
node dist/cli.js suite calibrate --xcresult /tmp/x.xcresult --fail-on-miss

# 一步闭环 + 审计产物
node dist/cli.js suite loop --calibration .artemis/design/reports/calibration-<stamp>.json
node dist/cli.js suite report          # xlsx + JUnit + 追溯矩阵
```

**CI 双轨建议**：

| 时机 | 内容 | 时长 |
|---|---|---|
| pre-merge | `build/test/lint`（服务仓库）+ `suite check`（项目侧，无设备） | 秒级~分钟级 |
| nightly / post-merge | `suite run --fail-on-uncovered --retry 1` → `suite calibrate` → `suite report` → `suite loop` | 长任务，次日看产物 |

**Excel 入料**（回归入口 `run_regression excelPath`）：首行表头「用例名/步骤」（可选：预期/前置/模块；**勿合并单元格**），最小样例：

| 用例名 | 步骤 | 预期 | 前置 | 模块 |
|---|---|---|---|---|
| 登录-错误密码 | 打开首页→点击登录→输入错误密码→提交 | 提示"密码错误"且不进入主页 | 应用已安装且可启动 | 登录 |

**项目机 runner 常驻化**（systemd/launchd 示例与注意项：勿双开同名、中心 PG 环境、产物令牌可选项）：见 README「项目机 runner」段。

### 3.7 设备接入

**Android（默认）**

```bash
adb devices                     # 已授权设备/模拟器
node dist/cli.js doctor
mobile_diagnose                 # 检查授权/锁屏/RSA/空闲；attempt_fix 可自愈
```

**iOS 模拟器**
- 把已启动模拟器的 UDID 传给 `--device` / `mobile_run_task.device_serial`，AOS iOS 后端（idb→simctl）接管截图/层级/复位；无头环境用 `scripts/adb-safe.mjs` 一类的硬超时封装或 CI 里预启动模拟器。

**iOS 真机（Appium + WDA）**
- 项目 `.env`（项目打底、进程 env 覆盖）：
  - `AOS_IOS_XCODE_ORG_ID`（签名团队 ID，**必填**）
  - `AOS_IOS_XCODE_SIGNING_ID`（默认 Apple Development）
  - `AOS_IOS_WDA_BUNDLE_ID`（默认 `com.aos.mcp.wda`）
  - `AOS_APPIUM_URL`（可选，直连已有 Appium；否则托管懒启动）
- iOS 18+ 一次性准备：`sudo appium driver run xcuitest tunnel-creation`
- 验证：`node dist/cli.js doctor` / `aos_status.ios` 显示 Appium、xcuitest、签名与隧道状态。

**远程设备宿主（Mac 集中部署、项目在其他机器，ADR-0011）**

服务端（Mac mini）与设备不在同一台机器时，用项目 `aos.config.jsonc` 的 `deviceHosts` 声明执行宿主（优先级：config < 项目 `.env` < 进程 env；映射到既有 env 键）：

```jsonc
{
  "deviceHosts": {
    "ios": {
      "appiumUrl": "http://192.168.1.100:4723",   // → AOS_APPIUM_URL
      "wdaBundleId": "com.devB.wda",               // 宿主侧签名覆盖：WDA 在宿主编译，team/签名必须在该宿主有证书
      "xcodeOrgId": "TEAMID",
      "xcodeSigningId": "Apple Development"
    },
    "android": { "adbHost": "192.168.1.100:5037" }  // → ADB_SERVER_SOCKET（tcp:host:port，可选）
  }
}
```

- 宿主侧准备：iOS 在开发者 Mac 上 `appium --port 4723`（真机插它，Xcode/签名/`tunnel-creation` 都在宿主侧）；Android 优先设备侧联网（`adb pair`/`adb connect` 到服务端，无需宿主），确有需要再让宿主机跑 `adb -a nodaemon server`（adb server 暴露风险，仅限可信网络）。
- 跨网推荐 SSH 隧道（零暴露）：`ssh -L 4723:127.0.0.1:4723 <宿主>`（iOS）或 `ssh -L 5037:127.0.0.1:5037 <宿主>`（Android），宿主地址分别写 `http://127.0.0.1:4723` / `tcp:127.0.0.1:5037`。
- 产物跨机：`app_path` 接受 `http(s)://`——iOS 由 Appium 宿主下载安装（跨机安全），Android 由服务端下载到 `.artemis/cache/apps/` 后 `adb install`；iOS 本地 `.ipa` 路径语义要求该路径**在 Appium 宿主可读**，跨机请用 URL 或预先用 Xcode 装好。
- 限制与体检：iOS 模拟器只能跟服务本机（idb/simctl），远程宿主只覆盖真机；`doctor` 会探活宿主（iOS `/status`、Android adb `host:version`）并在失败时给出隧道/暴露提示；`aos_status.deviceHosts` 显示当前解析结果。

## 5. 排障速查

| 症状 | 第一步 |
|---|---|
| 工具列表缺 `mobile_*` / "artemis 子进程未就绪" | `doctor` → `mobile_diagnose`；看 `.artemis/logs/aos-mcp.log` 依赖状态行 |
| `setup_required` | `aos_configure`（LLM 或 Figma token）；`aos_status.setup` |
| 任务失败 | `aos_tasks` 取 trace → `.artemis/traces/<id>/stderr.log`；`mobile_inspect_trace`；`mobile_diagnose.logs.last_failed_task` |
| LLM 401 / 超时 / 余额 | `llm_list` 看 active 与 key 来源 → `llm_switch` / `aos_configure` |
| 模型下线/不可用 | `llm_models refresh`；自动修复日志；`AOS_LLM_AUTO_REPAIR=0` 时手动换模型 |
| Figma 桥不通 | `aos_status.figma.bridge`、3055 端口占用；无桌面则改用 REST token |
| Figma REST 限流 | 快速失败并给 retry-after；`AOS_FIGMA_RETRY_MAX_WAIT_MS`/`AOS_FIGMA_CACHE_TTL_MS` 可调；访客席位建议换编辑席位 |
| `figma_generate_tests` 报"流程覆盖不完整，未落盘" | 看响应/错误里的未硬覆盖清单（inferred 探索缺口仅报告、不触发）；补原型连线或调大 `maxFlows/maxDepth`；确认后重跑 |
| `suite check` exit 2 | 未硬覆盖屏幕/跳转、路径截断、缺 flows.json（fail-closed），或 `--strict` 弱断言命中；按输出修复后重跑 |
| `suite run --fail-on-uncovered` exit 2 但用例都 PASS | 硬覆盖不完整（含缺 flows/截断；inferred 探索缺口不触发）——这正是闸门；或改 `--allow-uncovered`（不推荐） |
| `suite calibrate` 漏报率高 | 复核 MCP 判定/断言（漏报=XCTest 失败而 MCP 通过）；补断言或查等待/数据 |
| 重试后转绿但 exit 1 | 设计如此：**首跑失败仍决定门禁**，重跑仅诊断（看 `retry.flaky` 标注） |
| pen 合成结果碎片/错名 | 看 `flow-map.md` 警告（`pen-generic-names`/`pen-state-merges`）；修正标签/顺序后重跑 `pen_extract_flows` |
| pen CLI 未安装/未登录 | 配 `PEN_CLI_KEY` 或 `AOS_PEN_CLI_PATH`；`doctor` 看状态；`AOS_PEN_NO_INSTALL=1` 时需预装 |
| PG 降级警告 | 配 `MOBILE_TESTING_DATABASE_URL`，否则台账仅进程内有效 |
| API 错误未产出/未匹配 | 检查 `.artemis/design/error-codes.json` 与 `match` 正则；`suite api-errors <traceId>` 复算看 degraded（`registry-missing|registry-empty|no-window|…`） |
| artemis 依赖过期 | `doctor --install-deps`（或配 `AOS_ARTEMIS_DEPS_URL` 离线包） |
| iOS 真机连不上 | `aos_status.ios`；签名 `AOS_IOS_XCODE_ORG_ID`；iOS 18+ 隧道命令；Appium 端口占用 |
| 真机日志降级 | `ios-log-tool-missing`＝装 libimobiledevice（`brew install libimobiledevice`）或设 `AOS_IDEVICESYSLOG_PATH`；`window-elapsed-live-tail`＝采集晚于任务窗口（尾采样近似，正常现象）；结果带 `clockWarning` 表示窗口近似 |
| 改了 `dist/` 但行为没变 | 构建后需**重启 MCP 客户端会话**（`aos_status.build.stale=true` 会提示） |
