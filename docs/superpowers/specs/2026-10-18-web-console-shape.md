# Web 控制台设计简报（Shape Brief）——CSDC 风格 · 数据底座 · 下发任务闭环

> 依据：`PRODUCT.md`（强制记录＝产品定位）＋ impeccable shape 流程（本文件为确认用简报，不写代码）
> 参考：CSDC 开发者设计系统 `https://html.temvo.com/CSDC/`（tokens 已存 `.scratch/web-console/references/csdc/`）
> 决策记录（用户已确认）：里程碑**并行推进**（记录底座 ∥ 控制台 UI）；动作边界**六类全开放**（均带确认与审计）；承载**原地升级**（`/panel`＋`/usage` 融合为控制台）。

---

## 1. 用途与受众（Job & audience）

- **模式（visitor mode）＝ Operate**：工具型操作台；扫描效率、一致性、真实使用场景优先，品牌表达落在精确细节（CSDC 体系）。
- **三类用户，全部覆盖**：
  - 测试/QA 工程师：日常"下发→看结果→定位→复用"；以单项目为主。
  - 多项目管理员：看多项目健康、runner 在线、存储/保留、审计；以总览为主。
  - 研发自查者：改完代码/设计稿跑一轮，顺手看报告。
- **成功的样子**：任何人在 1 分钟内完成"选目标 → 下发 → 知道在跑哪台/哪个设备 → 结果与证据可查 → 失败可定性/可建单 → 下次可直接复用上轮数据"。

## 2. 成果与证据（Outcome & proof）

- **主任务**：
  1. 下发一次测试（回归任务/Excel 导入/范围选择）；2. 跟踪到结论（gate/通过率/失败域）；3. 一键回溯证据（批次/轨迹/截图/差异/崩溃/API 错误）；4. 定性（裁决）与建单；5. 复用（基线与范围）。
- **成功度量（产品内可观察）**：下发流程步数 ≤4、回到"正在跑什么"≤1 次点击、任一失败条目到证据 ≤2 次点击、控制台写入动作 100% 有审计事件。
- **产品特有真相**：记录强制持久且分三类（结果/过程/数据），控制台与 MCP 工具、CLI 共用同一数据面——**不存在"只有这次会话可见"的默认态**。
- **Evidence on hand**：本仓库 `.artemis/` 真实数据（批次/轨迹/崩溃/用例集）；本机 PG17；1532 测试基线；CSDC 参考文件。不可虚构客户/基准数据。

## 3. 选定方向（Selected direction）

- **视觉权威 = CSDC**（用户绑定，原样采纳；不做二次演绎）：
  - Token 映射：强调黄 `#FFE600`（主行动/焦点）、语义色 成功`#34C759`/错误`#FF3B30`/警告`#FF9500`、链接`#0066CC`；文本三级 `#1D1D1F/#6E6E73/#86868B`；面色 `#F5F5F7/#FFFFFF/#EFEFF2`；边框 `#D2D2D7`；圆角 6/10/14/18/980；阴影两档；顶栏毛玻璃 `blur(20px)`。
  - 版式：SF Pro/PingFang 栈；标题紧字距；正文 0.9375rem/1.55；等宽 SF Mono 展示 ID/路径。
  - 结构母版取自 CSDC `#layout` 示例：毛玻璃顶栏＋左侧分区导航＋主区卡片/表格；黄色卡片专用于"当前焦点/待办"。
- **结构性主张（interaction thesis）**：
  - **一屏三问**：项目页第一屏回答"健康吗？在跑什么？接下来做什么？"；下发是主干动作、常驻可见。
  - **动作即导航**：空态/列表/详情都给出下一步动作（下发、重跑、看证据），不做"死胡同页面"。
  - **同一数据三种口径**：总览（跨项目）/项目（单项目）/条目（批次/任务/用例）逐层下钻，链接即真相，数字可点回源。
  - **记录可见化**：把"记录"做成产品：每个写入动作产生审计事件；数据底座状态（台账位置/持久层/保留期）常驻可见。
- **实现后果**：沿用服务端渲染 HTML＋内联 CSS（无前端构建链）；CSDC 以 CSS 变量落地一份 `tokens`；交互用表单 POST＋fetch（现有模式升级：确认、进度、错误回显）；`meta refresh` 仅用于活跃态自动刷新，不做轮询风暴。

## 4. 范围与边界（Scope & boundaries）

- **在范围内**：升级后的统一控制台（路由原地：`/panel`、`/usage` 保留兼容；新增动作 API 命名空间 `/panel/api/*` 或 `/console/api/*` 由实现计划定）：总览、项目、任务、下发向导、用例库、档案与产物、运行机、计划、运维与数据、审计。
- **六类动作全开放**（均需确认与审计）：
  1. 下发与执行：创建回归任务（份×端×基线）→ 指派 runner/手动设备执行；任务释放与重跑。
  2. 导入与范围：Excel 文档导入用例库；范围（功能/关键词）批量下发。
  3. schedule 管理：创建/启停/删除、下次触发回显。
  4. 裁决与建单：批量裁决（case-defect/execution-deviation/app-defect/uncertain）、一键建 Jira 单（外部副作用，默认 dryRun 预览后确认）。
  5. 资产与保留：quarantine 管理（owner/到期）、保留期查看与清理策略（清理需输入确认短语）。
  6. 运维与导出：存储状态（持久层/位置/迁移）、runner 健康、数据导出（结果/过程/数据）。
- **保真度**：production-ready 全流程（非 prototype）；明暗：以 CSDC 亮色为基准（CSDC 未提供暗色 token，暗色列为开放项）。
- **不动**：根 `DESIGN.md`（架构事实源）、CLI 语义与退出码、MCP 工具 schema、既有数据文件结构（新增而非迁移破坏）。
- **反目标（明确不做）**：纯展示的"记录陈列页"；为好看牺牲信息密度；引入前端框架/构建链；把危险动作做成一次点击即执行；伪造数据/演示占位冒充真实。

## 5. 状态与量级（States & ranges）

- **状态**：首访（空态要给"接入检查＋第一步"）、加载、错误（人话＋恢复建议）、权限（动作未启用：解释开关与配置）、降级（无 PG/无 runner/无设备：**如实且可行动**，禁止"降级"式误导词，统一为"未配置 X → 影响 Y → 这样启用 Z"）、活跃态（运行中/待执行自动刷新 10s）、溢出（长名/长路径截断＋title 全文）。
- **量级**：单项目用例集 10–200 份、每份 1–200 用例；单任务 1–50 用例×多设备；多项目 5–50；事件流 1e4–5e4 条（分页/筛选）；runner 1–20；并发写入低（人工操作域）。
- **内容真实性**：所有数字/来源（导入自/生成自）来自台账与产物事实源；空数据就显示空态，不做假样本。

## 6. 交互与布局（Interaction & layout）

**信息架构（顶栏毛玻璃＋左栏分区）**：

```
总览（多项目）｜项目｜任务｜下发｜用例库｜档案与产物｜运行机｜计划｜运维与数据｜审计
```

**页面功能规划（每页：目标 / 区块 / 动作）**：

1. **总览**（跨项目）：项目表（健康灯/栈/最近批次/趋势/待办/runner）、存储与保留摘要、全局快捷键；动作：切项目、进下发、导出总览。
2. **项目**（单项目驾驶舱）：健康（凭据/存储/设备/runner）、**在跑什么**（活跃任务卡）、**待办**（未裁决/未建单/积压）、最近结果（批次小表＋趋势）、快速下发入口；动作：下发、重跑、看证据、裁决入口。
3. **下发向导**（核心，4 步）：①来源（用例库选份 / Excel 导入 / 范围关键词）②参数（端、设备或 runner 自动、基线 latest/none、是否立即执行）③**预览回显**（功能×条数×来源×设备×将跑用例数）④确认派发；派发后落任务详情。含校验错误与空态引导。
4. **任务列表/详情**：状态机（pending→claimed→running→completed/partial/failed）、领取方（在线/失联）、子运行（设备×份）、同份对比（修复/回归/新增/消失）、跨端差异、产物链接（批次清单/报告/证据）；动作：释放重跑、按任务出报告、查看审计。
5. **用例库**：份列表（来源：导入自 x/生成自 y、功能、条数、时间、truncated 标注）＋份详情（用例清单、taskDesc 预览）；动作：导入（向导）、quarantine、按份下发、删除（保留策略）。
6. **档案与产物**：检索（时间/域/关键词）：批次清单、轨迹（截图/日志）、报告（xlsx/JUnit）、差异（标注图）、崩溃；动作：下载/导出、跳任务。
7. **运行机**：在线状态/心跳/设备清单/版本/产物服务令牌状态、领取历史；动作：提示配对与排障，不放"杀进程"。
8. **计划**：schedule 列表（下次触发/上次结果/lastNote）、创建（引用份×端×周期）；动作：启停/删除（确认）。
9. **运维与数据**：存储（持久层：文件台账/PG；位置；一键迁移指引）、保留期（各类资产超期统计）、导出（结果/过程/数据 三口径 JSON/CSV）；动作：导出、迁移指引、"清理预览"（只预览，执行需短语确认）。
10. **审计**：服务内部编排事件流（导入/执行/回写/降级/跳过/写入动作），按时间/域/结果筛选；每条可跳关联对象。

**交互模式**：动作反馈（提交中/成功回显/失败可重试）；批量（裁决、建单、下载）＝勾选＋汇总条；确认分级（只读无确认／常规写入单次确认／外部副作用 dryRun 预览＋确认／清理类输入短语）；键盘：/ 聚焦搜索、g 前往、? 快捷键表；可访问性：对比度 AA、焦点可见、表格语义、错误与状态用文字＋图标不只颜色。

**响应式**：≥1280 三栏（导航/主区/上下文），768–1280 两栏（导航折叠），<768 单列（导航抽屉、表格转卡片列表）——管理台以桌面优先，移动端保底可读可操作。

## 7. 约束与开放决策（Constraints & open decisions）

**并行工作流 A：记录底座（B 形态＝强制持久）** ——与 UI 并行实现：

- **A1 强制持久**：新增**文件台账**为默认（项目 `.artemis/ledger/`持久，零配置）；PostgreSQL 作为集中/多机升级；废弃"内存即默认"路径（测试环境除外）。含：启动自愈（从磁盘重建用例集/批次登记）。
- **A2 内部编排审计**：统一事件记录每次服务内部动作（导入/执行/回写/裁决/降级/跳过/存储迁移），字段：时间/域/动作/结果/关联（traceId/caseId/taskId/runId）/摘要；落文件＋台账，控制台"审计"页可查。
- **A3 产物索引**：对 `.artemis/` 产物建立可检索索引（批次/轨迹/报告/差异/崩溃），支持筛选与导出。
- **A4 查询与导出**：JSON/HTTP（控制台复用）＋CLI；导出三口径：测试结果、测试过程、测试数据。
- **文案整改**：清除"内存降级"类误导表述（面板徽章、`aos_status`、doctor、usage、命令输出，共 11 处），统一为"未配置 X → 影响 Y → 启用 Z；产物已落盘不受影响"。

**并行工作流 B：控制台 UI（CSDC 原地升级）**：

- B1 CSDC token 落地（单一 CSS 变量源）＋布局母版；B2 只读页重构（总览/项目/任务/档案/运行机）；B3 下发向导＋动作 API＋确认/审计接线；B4 用例库/计划/运维与数据/审计页；B5 移动端保底与 AA。

**开放决策（实现计划中定，或请你纠正）**：

1. 动作 API 命名空间：延续 `/panel/api/*` 还是新起 `/console/api/*`（路由兼容策略）。
2. 文件台账格式：JSONL 追加＋周期性快照（推荐，易审计、易导出）vs SQLite（更强查询、加依赖）。
3. 视觉设计文档落点：建议 `web-console/DESIGN.md` 作为控制台表面专属视觉体系（impeccable 管理），**不动根 `DESIGN.md`**（架构）。
4. 暗色主题：CSDC 未给暗色 token——先只做亮色，或自拟暗色映射（列为后续）。
5. 审计事件保留期与上限（默认 90 天/5 万条，与 usage 对齐）。

**决策落定（用户"继续"＝采纳推荐项）**：

1. 动作 API 命名空间：**沿用 `/panel/api/*`**（新增子路由；不另起 /console/api）。
2. 文件台账格式：**JSONL 追加＋周期快照**（零依赖、可审计、可导出）。
3. 视觉设计文档落点：**`web-console/DESIGN.md`**（控制台表面专属视觉体系）；不动根 `DESIGN.md`。
4. 暗色主题：**先做亮色**（CSDC 体系），暗色列为后续。
5. 审计保留期：**默认 90 天 / 5 万条**（与 usage 对齐，可配）。
