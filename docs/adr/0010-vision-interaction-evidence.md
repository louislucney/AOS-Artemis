# 视觉交互识别的证据等级与门禁豁免（vision-inferred）

`.pen`（v2.20）没有原型交互字段，Figma 中也存在无原型链接的节点：仅凭结构无法理解「图标即入口」这类交互，设计标注是否清晰不应成为识别前提。现引入视觉识别阶段：对设计渲染图识别交互元素与意图，产出元素清单（`flows.json` 升 schemaVersion 3，`screens[].elements[]`），其证据来源为新增枚举 `vision-inferred`（低置信）。它只生成带未决目的地的探索步骤（`to:null`，进 `unresolvedDestinations`），不猜目的地、不作硬断言；覆盖率门禁对其豁免（缺口仅报告）；验证与升权只经外部证据——真机观测命中或人工确认（沿用既有对账闭环）。视觉不可用时显式降级（`vision-unavailable`）并保持既有推断，不阻断任何门禁。这是 ADR-0007/0008 的延伸：新来源进入同一 provenance/confidence 分流，不新开权威。

## Considered Options

- 允许目的地猜测（按同名屏匹配）：幻觉直接变成边，拒绝。
- 视觉结果直接成硬断言、参与硬闸：污染门禁、制造门禁疲劳，拒绝。
- provenance 采用可扩展字符串：未登记值经 `resolveProvenance` 落 `legacy-unknown`，而覆盖率门禁对 legacy 按硬闸处理——新来源会被旧消费者当成硬门禁目标，拒绝松散字符串（新值必须显式入枚举，并同时更新断言侧与门禁侧两个分流函数）。
- 视觉不可用时阻断门禁：与「推断/探索缺口只报告不阻断」冲突，且令 pen 离线价值归零，拒绝。
- 模型自审作为纠错仲裁：无外部信息、自我确认，只允许去重/排序，拒绝作权威。
- 独立 elements.json：与 flows.json 易失同步，拒绝。

## Consequences

- 新增来源值是破坏性变更：flows.json schemaVersion 提升到 3，消费者必须认识该值（旧代码会把它归入 `legacy-unknown` 硬闸）。
- 视觉误识别的最坏后果是探索噪音，不是假门禁；代价是识别结果默认不进硬覆盖率。
- 视觉依赖模型能力声明与渲染通道（Figma token / pen 登录），两者不可用都必须显式标注，不静默。
- 先 pen 后 Figma，共用同一元素清单契约；「识别与纠错」由真机观测闭环验证。
