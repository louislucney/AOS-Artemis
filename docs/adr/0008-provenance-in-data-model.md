# 交互证据的来源与置信度进数据模型（provenance/confidence）

流程解析、用例生成与执行此前把不同可信度的证据平权消费：不确定性只存在于 warnings 文案与「（INFERRED）」字样，下游无法按来源分流。现为 screen/edge/step 增加机器可读的来源（显式交互 / 推断 / 真机观测 / 人工确认）与置信度；生成、执行、门禁与报告按来源分流——推断边默认只生成探索步骤，硬断言需观测或验收标准/人工确认背书。这是「双源对账 + 升级」闭环得以实现的前提。

## Considered Options

- 维持现状（prose 警告与文案标记）：机器不可消费，下游无从降级/阻断，拒绝。
- 旁挂 sidecar（独立 provenance 文件）：与主体数据易失同步、消费方需两处拼装，拒绝。
