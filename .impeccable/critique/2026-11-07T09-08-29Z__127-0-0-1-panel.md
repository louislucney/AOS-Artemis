## Design Specificity Verdict

**内容非常具体，交互非常通用，视觉作者性中等。**

- 具体：`用例集/份/裁决/失败域/门禁/隔离/执行机/租约/批次/证据/trace/APK/IPA/MCP runner/Figma/Jira`，以及“记录底座/页面缓存/证据已清理”的 provenance，是只有移动测试平台才有的。
- 通用：去掉这些词，外壳就是任意 CI/CD 后台——顶栏+侧栏+黄色卡片头+tab+表格+“下载 agent”。产品最核心的 `设计→用例→任务→批次→用例结果→证据→裁决→重跑` 链路没有在界面上形成一条可见的线。
- 最像本产品的页面是下发向导，而它恰好是当前最不能闭环的页面；最先看到的总览页则最通用。

## Overall Impression

一句话：**它知道很多，但不会把用户带到下一步。**

项目页的“下一步”卡片是全场最好的时刻；但用户点进“新建测试”后，会在 host 选择处撞墙；即使下发成功，任务详情也只给状态和“清单”，没有批次、trace、截图、日志、失败分析、重跑失败用例。控制台能创建任务，却不能帮助用户完成调查。

## What's Working

1. **Provenance 是一等公民**：存储层、页面缓存年龄、构建新鲜度、runner 在线/离线、证据存在/已清理、审计恢复——这直接支撑“记录即产品”，应保留并强化。
2. **高风险动作有门禁**：下发/取消/停止有 inline confirm，Jira 建单有预览+外部副作用确认，角色/能力 banner 和审计行都在。
3. **领域交叉链接放在了对的地方**：项目页“下一步”、用例集行“下发该用例集”、审计“恢复”、`?` 术语、`g` 快捷键，说明团队理解工作流；问题是页面之间没有共享同一个状态机。

## Priority Issues

### [P0] 下发向导在当前数据下无法完成

**是什么**：`hostNavScript/projectNavScript` 把 `create&type=suite` 作为一个 `section` 值，生成 `section=create%26type%3Dsuite`；服务端不识别，改 host/project 会跳回项目页并丢掉已选用例集/端/安装包。与此同时，唯一在线 host `win-runner-01` 没有登记 ESSO-GU，选中直接显示“该主机尚未登记项目”并禁用确认；界面没有绑定 project→host 的动作，“MCP 原生接入”只跳到下载页。下发页也没有设备选择器。

**为什么重要**：这是产品的主动词。一个不能下发的控制台只是 viewer；对第一次使用的 Jordan，这是直接死路。

**修复**：修正 `section` 编码；host/project 切换用链接或保留表单状态；在下发阻塞处提供真正的“把项目接入该执行机/绑定”动作，或允许跨 root runner 使用中心默认项目；增加设备选择或明确列出“将自动选择的可用设备”；把禁用原因放到 `确认派发` 旁。

### [P0] 任务页显示 0 条，对比页显示 15 失败，失败记录无法打开

**是什么**：任务页/项目页/搜索过滤掉 `jobSpec !== null` 的旧 Web 任务；对比页仍统计它们；旧 `section=jobs&job=` 重定向到任务详情，而任务详情对 Web 任务返回 404。

**为什么重要**：在“记录即产品”的产品里，两个页面给出互相矛盾的数字，且用户无法打开任何一个失败记录。这会直接摧毁对台账的信任。

**修复**：二选一，且只选一个口径：要么恢复 Web 任务的一等只读列表/详情，要么把对比页/审计页的 Web 任务统计也隐藏并标明“历史 Web 任务不在此口径”。不能显示一个无法点开的失败数。

### [P0] 任务详情是状态页，不是结果工作台

**是什么**：运行行只有“清单”；没有批次、trace、截图、日志、失败分析、重跑失败用例的链接；CLI 命令只给文字。

**为什么重要**：闭环的第二半是“发生了什么、证据在哪、下一步做什么”。现在用户只能拿 task id 回终端。

**修复**：每个 run 行链到批次页；加“去失败分析”“重跑失败用例”；证据链接直接出现在 run/case 行；CLI 命令加复制按钮。

### [P1] 设备页是接入说明书，不是设备控制台

**是什么**：有在线 runner 和空闲设备，却只有下载/刷新；没有“用此设备下发/跑冒烟/释放租约/注册项目”；项目上下文丢失；1100px 表格被裁。

**为什么重要**：设备页本应成为下发阻塞时的修复入口，现在反而强化死路。

**修复**：保留项目上下文；合并重复 host；把当前任务/租约放进可见列；每行加“用此设备下发”“跑冒烟”；加“注册项目”动作；表格改成卡片或可展开行。

### [P1] 页面自相矛盾且关键布局在 1440px 崩坏

**是什么**：`安装包` tab 上传器写“Excel 用例”；`执行机与设备在下一步选择` 但下一步没有设备；`4 份可引用用例集` vs `1 份用例集`；`健康`=runner 在线；`用例库/测试资产/用例集` 三种叫法；对比页 1440px 项目名一字一行；任务搜索按钮 1148px 全宽；每个卡片头同权重黄色。

**为什么重要**：这些不是装饰问题，而是让控制台显得不可信；对 Sam，对比页和移动导航直接不可用。

**修复**：统一动作/对象词汇；按 `tab` 预选上传类型；`[hidden]{display:none!important}`；修正 grid 表单；对比表固定列宽/横向滚动容器；移动导航加 overflow 菜单；空态给按钮。

## Questions to Consider

1. 如果下发是产品的主动词，为什么唯一在线 host 没有项目，且界面没有修复按钮？“host” 是用户概念，还是内部实现泄漏？
2. 设备页已经知道设备空闲，为什么只给下载？如果设备行本身就是“用此设备下发”，会怎样？
3. 结果页为什么不链到结果？如果批次页在别处，为什么任务页是下发后的落地页？
4. 控制台说 0 条任务、15 条失败，QA 该信哪个？如果答案是“Web 任务”，它们的页面在哪里？
5. 如果每个卡片头都是黄色，警告色还剩下什么？当前步骤应该长什么样？
6. “记录即产品”如果记录只能以原始路径出现在文件索引里，用户无法跟随，那它是存储还是产品？

## 补充证据（链接审计）

资产页“下一步：去新建测试”的原始 `&section=create` 未转义，浏览器把它解析成 `§ion=create`。现场已经出现一个伪项目行/目录 `ESSO-GU§ion=create`（对比页可看到两条 ESSO-GU，其中一条带 `§ion=create`）。这既是死链，也是数据污染；修复链接后应清理该伪项目。
